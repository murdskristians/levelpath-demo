# Plan: Edit a draft purchase request before submitting it

> Spec: agents/b0697309/spec.md · Type: feature

## Approach

Add `PUT /purchase-requests/:id`, with a service method shaped like `submit`:

1. `isUuid`, or `404`.
2. Read the row inside `withTenant`, filtered on the caller as `requester_id`, or `404`.
3. A row that isn't a draft is a `409`.
4. Run a conditional `UPDATE … WHERE id AND requester_id AND status = 'draft'` that sets the six fields and `updated_at = now()`. No row back is a `409`, and a key violation (the supplier's composite FK) is a `404`, as in `create`.

The body schema is `createPurchaseRequestSchema`, exported again as `updatePurchaseRequestSchema`, so create and edit can't drift apart.

On the web, `NewRequestForm` takes an optional `initial` request. It seeds its state from that request and switches its name and its submit label. `App.tsx` replaces the `formOpen` boolean with one `form` state (`create`, or `edit` with the request), so one form shows at a time, in the same place.

**Why `PUT` with the create schema, not `PATCH` with a partial schema:** the intake asks for the same fields and the same validation, and the form always sends all six. A partial schema would be a second set of rules to keep in step, and `PATCH` with the create schema's defaults would quietly reset fields the client left out.

**Why one form component, not an `EditRequestForm`:** the intake asks for "the same form", and Suggest fields, validation and the error mapping already live in it.

### 2. API service and route

In `purchase-requests.service.ts`, import `UpdatePurchaseRequest` and add, after `submit`:

```ts
/** The caller's own draft gets new field values; it stays a draft. */
update(user: AuthUser, id: string, input: UpdatePurchaseRequest): Promise<PurchaseRequest> {
  if (!isUuid(id)) throw new NotFoundException();
  return this.db.withTenant(user.tenantId, async (trx) => {
    const request = await trx
      .selectFrom('purchase_requests')
      .select(['id', 'status'])
      .where('id', '=', id)
      .where('requester_id', '=', user.userId)
      .executeTakeFirst();
    if (!request) throw new NotFoundException();
    if (request.status !== 'draft') throw new ConflictException('only a draft can be edited');
    let updated: { id: string } | undefined;
    try {
      // Conditional on the owner and the status, so an edit racing a submit changes nothing.
      // Never tenant_id, requester_id, status, id or created_at.
      updated = await trx
        .updateTable('purchase_requests')
        .set({
          supplier_id: input.supplierId,
          title: input.title,
          amount_cents: input.amountCents,
          currency: input.currency,
          category: input.category,
          description: input.description,
          updated_at: sql<Date>`now()`,
        })
        .where('id', '=', id)
        .where('requester_id', '=', user.userId)
        .where('status', '=', 'draft')
        .returning('id')
        .executeTakeFirst();
    } catch (err) {
      // The composite foreign key to suppliers: unknown, or another company's.
      if (isKeyViolation(err)) throw new NotFoundException();
      throw err;
    }
    if (!updated) throw new ConflictException('only a draft can be edited');
    return readBack(trx, id);
  });
}
```

The `catch` follows the `create` pattern: it turns the key violation into a typed `NotFoundException`, and rethrows everything else. Throwing inside `withTenant` rolls the transaction back.

## Notes

- **Don't touch `db/`:** no migration, and no seed change.
- **Field order:** keep the `set` and the schema in the order shown. The web test compares the exact JSON string the form sends, and that order is the Zod output order (`title, amountCents, currency, supplierId, category, description`), the same as the create test.
- **The ownership filter goes on the `UPDATE` too,** not only on the read. It costs nothing, and it keeps the write correct on its own.
- **Leave `selectPurchaseRequests`, `toPurchaseRequest` and `readBack` as they are.**
- **Seeded rows:** `seededRequestsSnapshot` compares `title, amount_cents, status, updated_at` of the seeded rows. No test may change a seeded row, and neither may the manual checks above.
- **The `catch` in `run` (App.tsx):** it sets the alert and returns `false`, a typed fallback. Keep it, and don't add a silent `catch` anywhere.
