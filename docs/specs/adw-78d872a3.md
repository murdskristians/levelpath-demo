# Light/dark theme toggle

> Issue #61: Add a light/dark theme toggle to the web app · Type: feature · Intent: none

## Summary

- A header button, next to the user picker, switches the web app between a light and a dark theme.
- On a first visit the theme follows the OS (`prefers-color-scheme`); after a click the choice is kept in localStorage, separate from the stored user id.
- The theme is applied before first paint (inline script in `index.html`), so there is no flash.
- All colours in `App.css` become CSS custom properties; light values are unchanged, dark values meet WCAG AA.
- Web app only: no API, database or shared-package change.

## Context

- `apps/web/src/App.tsx`: `App` builds `picker = <UserPicker …/>` and passes it to `Dashboard` (header with picker and identity) or renders it in a bare `<header>` when no user is picked. Both headers show the same `picker` node.
- `apps/web/src/users.ts`: the existing localStorage pattern (`loadUserId`, `saveUserId`, key `levelpath.userId`).
- `apps/web/src/App.css`: every colour is a hard-coded hex (body, footer, empty state, buttons, header border, inputs, focus ring, notes, request list, badges, error alert, field error, suggested tag, form note, secondary button).
- `apps/web/index.html`: no script besides the Vite entry.
- `apps/web/src/App.test.tsx`: Testing Library tests with `localStorage.clear()` after each test. jsdom has no `matchMedia`.

## Requirements

1. A `Theme` is `'light' | 'dark'`. The stored key is `levelpath.theme`, distinct from `levelpath.userId`.
2. With no valid stored value, the theme is `dark` if `prefers-color-scheme: dark` matches, else `light`. Missing `matchMedia` means `light`.
3. The root element (`<html>`) carries `data-theme="light|dark"`; CSS custom properties are defined on `:root` (light) and `:root[data-theme='dark']` (dark). The page also sets `color-scheme` per theme.
4. A button in the header, in both the picked-user and no-user states, next to the user picker, toggles the theme. Its visible text and accessible name are always "Dark theme", and `aria-pressed` is `true` when dark is active, so the state is conveyed by `aria-pressed`, not the name.
5. Clicking writes the new theme to localStorage and updates `data-theme`. The choice survives a reload and a user switch (switching users neither resets nor changes it).
6. Invalid stored values are ignored (fall back to requirement 2). Throwing `localStorage` (get or set) must not crash the app; the theme still switches in memory and the failure is logged with `console.warn`.
7. No flash: an inline script in `index.html` `<head>`, before the Vite module, sets `data-theme` from the stored value or the OS setting using the same rules. React's initial state reads `data-theme` from the root, so both agree.
8. `App.css`: every colour is a custom property. Light values are byte-for-byte the current colours. Dark values meet WCAG AA: text pairs ≥ 4.5:1; borders, dashed borders and focus ring against the page background ≥ 3:1.
9. Not in scope of changes: API, database, `packages/shared`, a "system" option, per-user themes.

## Acceptance criteria

1. With nothing stored and `matchMedia('(prefers-color-scheme: dark)')` matching, rendering `<App />` gives `document.documentElement.dataset.theme === 'dark'` and the toggle has `aria-pressed="true"`. With it not matching (or `matchMedia` undefined), `light` and `aria-pressed="false"`. Verify: new Vitest tests.
2. Clicking the toggle flips `data-theme` and `aria-pressed`, and `localStorage.getItem('levelpath.theme')` equals the new theme. Verify: Vitest.
3. Stored `dark` with an OS preference of light renders dark; stored `light` with OS dark renders light (stored beats OS). A stored `"blue"` is ignored. Verify: Vitest.
4. Remount (`cleanup()` then `render(<App />)`) keeps the stored theme. Picking another user in the picker keeps `data-theme` and the stored theme unchanged, and the user id key still updates. Verify: Vitest.
5. The toggle is present in the no-user state and after a user is picked, in the same header as the "User" select. Verify: Vitest (`getByRole('button', { name: 'Dark theme' })` within `banner`).
6. With `localStorage.getItem`/`setItem` throwing, `<App />` renders, a click still flips `data-theme`, and `console.warn` was called. Verify: Vitest.
7. `apps/web/index.html` contains an inline script before the module script that sets `data-theme`; a test evaluates it (reading the file) against a stubbed storage and `matchMedia` for stored dark, stored light, none+OS dark, none+OS light, and throwing storage, and gets the right attribute without throwing. Verify: Vitest.
8. `App.css` has no hex colour outside the `:root` and `:root[data-theme='dark']` blocks; the `:root` values equal the hex values of the pre-change file (`git diff origin/main -- apps/web/src/App.css` shows only the moves to variables). Verify: Vitest reading the CSS plus the diff.
9. A Vitest contrast test parses both token blocks and asserts the ratios: text/background pairs ≥ 4.5 and border/outline-versus-background ≥ 3 for each pair listed in the plan, in both themes. Verify: `pnpm test`.
10. Manual: `pnpm dev`, open the app with OS dark, hard reload: no white flash; the list, form, decision queue (as Amir), error alert, badges and footer all read well in dark. Verify: page.

## Tenant isolation and security

Not affected: no API, database or tenant data is touched. The only new stored value is a non-sensitive theme string in localStorage. The inline script reads only that key and uses it only if it is exactly `light` or `dark`, so stored content is never injected into the DOM as markup.

## Out of scope

- A third "system" option, theme per user, syncing across tabs.
- Any change to `apps/api`, `db/`, `packages/shared`, or protected paths.
- Redesigning the light theme.
- A CSP or nonce for the inline script.

## Assumptions

- Button label is "Dark theme" with `aria-pressed` (a toggle button for dark mode) rather than a label that changes: keeps the name stable for assistive tech.
- Storage key `levelpath.theme`: matches the existing `levelpath.userId` naming.
- Spec tolerates no `matchMedia` (jsdom) by treating it as light.
